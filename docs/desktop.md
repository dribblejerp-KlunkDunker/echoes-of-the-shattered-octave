# Desktop packages

An Electron shell in `desktop/` wraps the browser game for Windows, macOS and Linux. It loads the game **unchanged** from the repo root (in development) or from `resources/game` (in a packaged build, copied by electron-builder). Nothing in `index.html`, `js/`, `css/` or the tests is modified for it. The game stays fully playable in a plain browser.

## Build and run locally

Requires Node 20 or newer and npm. Electron and electron-builder are pinned in `desktop/package.json` (Electron 44.9.0, electron-builder 26.15.3).

```
cd desktop
npm install
npm start                 # run the game in the shell from the repo root
npm run icons             # regenerate build/icon.png and build/icon.ico (procedural stand-in)
npm run dist:linux        # AppImage + deb  (build on Linux)
npm run dist:win          # nsis installer + portable exe  (build on Windows)
npm run dist:mac          # universal dmg  (build on macOS)
```

Outputs land in `desktop/dist/` (git-ignored, as is `node_modules/`). Build each target on its own OS: `.dmg` needs macOS tooling, and NSIS/portable are most reliable on Windows. `.github/workflows/desktop.yml` does exactly that on native runners, on a `v*` tag push or by manual dispatch, uploads each OS's packages as artifacts, and on a tag also creates a draft GitHub release. It needs no secrets to run.

On Linux as root (containers, CI) Electron refuses to start without `--no-sandbox`; that is a root-only flag for testing, not part of the app.

### What the shell does

- `BrowserWindow` with `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, no preload, no remote module, devtools only when unpackaged.
- Files are served by a read-only custom protocol, `app://game/`. It is a "standard, secure" scheme so the game gets a real persistent origin: `localStorage` saves, `AudioContext`, full screen and pointer lock behave as on https. Only `index.html`, `css/`, `js/`, `img/`, `fonts/` and `music/` are served; path traversal and everything else (tests, `desktop/`, `.git`) returns 404. MP3 Range requests are supported.
- Strict CSP on every response: `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' blob: data:; font-src 'self' data:; connect-src 'self' blob: data:; ...`. No remote origin appears anywhere, no inline script, no eval. Inline style is allowed because the modules inject `<style>` elements. A second filter in the session cancels any request that is not `app:`, `data:` or `blob:`.
- Only the `fullscreen` and `pointerLock` permissions are granted; everything else is denied. Gamepad needs no permission in Chromium.
- New windows are denied; navigation away from `app://game/` and webviews are blocked; the window title is fixed.
- F11 (Ctrl+Cmd+F on macOS) toggles full screen from a minimal Game menu; Alt+Enter is handled by the game itself. Menu bar auto-hides on Windows/Linux.
- Single-instance lock; saves live in the app's own storage (`userData`), so the in-game save code remains the backup route.
- Electron fuses: `runAsNode` and Node CLI inspect/env options off, ASAR integrity on.

## Signing

Unsigned packages run, but users see warnings. None of this can be done without the owner.

**Windows (Authenticode).** Unsigned: SmartScreen shows "Windows protected your PC" until the file builds reputation. Options: an OV certificate (about 100 to 300 USD per year, shared reputation builds slowly), an EV certificate (about 250 to 500 USD per year, hardware token, immediate SmartScreen trust, awkward in CI), or Azure Trusted Signing / Artifact Signing (about 10 USD per month, cloud, CI friendly, eligibility depends on region and organisation history). Needs from the owner: a verified legal identity, the certificate or an Azure account, and the secrets `WIN_CSC_LINK` (base64 .pfx) and `WIN_CSC_KEY_PASSWORD`, which the workflow already reads. Azure signing needs an extra `azureSignOptions` block in the build config.

**macOS (Developer ID and notarization).** Required in practice: unsigned apps are blocked by Gatekeeper on current macOS (users must right-click Open or clear quarantine, and Apple Silicon refuses some unsigned binaries). Needs an Apple Developer Program membership (99 USD per year), a "Developer ID Application" certificate exported as .p12, and an app-specific password. Secrets: `MAC_CSC_LINK`, `MAC_CSC_KEY_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`. Hardened runtime and entitlements are already configured (`desktop/build/entitlements.mac.plist`). Notarization is turned on by electron-builder when the Apple variables are present. Add `"notarize": true` under `mac` in `package.json` at that point if your electron-builder version requires it.

**Linux.** No signing needed. AppImage and deb work unsigned; optional GPG signing of a future apt repository.

The workflow has the signing environment variables wired but empty; with no secrets set it builds unsigned and still succeeds.

## Auto-update

Options: (1) none, players download new releases by hand; (2) `electron-updater` with GitHub Releases.

**Recommendation: ship v1 with no auto-update, and add electron-updater later.** The game is offline, single-player and updates rarely, so the cost of a bad updater (a network-capable component in an otherwise network-free app, which also forces a CSP and request-filter exception in the main process) outweighs the benefit. Also, macOS auto-update only works for signed and notarized builds, and Windows updates of unsigned builds trigger fresh SmartScreen warnings. When signing exists, add: the `electron-updater` dependency, `publish: [{provider: github}]` in the build config, `autoUpdater.checkForUpdatesAndNotify()` in `main.js` behind an Options-style "check for updates" toggle default off, publishing `latest*.yml` files with each release, and a public repository (or a token for a private one). Saves are stored outside the app directory, so updates never touch them.

## Platform input verification

What was and was not verified in this sandbox (Linux container, Xvfb, no GPU, no physical devices):

| Area | Verified here | Still to check by hand |
|---|---|---|
| App starts, game boots, 4 bundled fonts load, title screen renders | Yes: unpackaged and from the built `linux-unpacked` package under Xvfb | Windows, macOS |
| `localStorage` writes inside `app://game` | Yes | Confirm a save survives quitting and relaunching on each OS |
| Full screen API (`requestFullscreen`) allowed | Yes: resolved and `fullscreenElement` set | F11, Alt+Enter and menu on each OS; macOS green button and Ctrl+Cmd+F; exit with Esc |
| Remote requests blocked, inline script blocked, window.open denied, traversal 404, MP3 Range 206 | Yes | n/a |
| Pointer lock | Permission is granted; the game's own capture logic is covered by `test/mouse-capture.test.js` | Real mouse: raw movement, no stuck cursor after alt-tab, Esc releases, works at window edge, trackpad on macOS |
| Gamepad | `navigator.getGamepads` exists; no device attached | Xbox, DualSense and generic pads: button mapping, hot-plug, focus loss, Steam Input overlay |
| Keyboard layouts | Not verified | QWERTY, AZERTY, QWERTZ, Dvorak, non-Latin layouts (game should use physical keys `event.code` for movement), IME on, dead keys |
| High-DPI | Not verified | 100/125/150/200 percent on Windows, Retina on macOS, fractional scaling on Wayland; canvas sharpness and cursor alignment |
| Audio | Not verified (no audio device) | `AudioContext` starts after the first click, music streams, volume and mute, no crackle at 44.1 vs 48 kHz |
| Installers | Linux AppImage and deb built; not installed | NSIS install/uninstall and portable on Windows; dmg drag-to-Applications and first launch on Intel and Apple Silicon; deb install on Ubuntu/Debian; AppImage needs FUSE 2 on some distros |

Checklist per OS: launch from the installer, start a new game, move with keyboard and mouse look, open each panel, toggle full screen both ways, plug in a gamepad, save and quit, relaunch and load, play ten minutes with music on, resize to 640x400, move the window between monitors with different scaling.
